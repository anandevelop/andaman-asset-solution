# เฟส 9 — หน้าแรกแบบ page builder (แผน ยังไม่ลงมือ)

> อ่านก่อนตัดสินใจ: แผนนี้เขียนหลังอ่าน `lib/home-sections.ts`,
> `app/[locale]/admin/(content)/pages/home/{sections,hero,gallery,cta}/`,
> `app/[locale]/(site)/page.tsx` (`SECTION_RENDERERS`) และ `components/CompanyIntro.tsx`
>
> **ข้อสรุปสั้นที่สุด: อย่าทำตามรูปที่ mockup วาดไว้** — ซ้ายเป็นรายการ section
> ขวาเป็นฟอร์มของ section ที่เลือก จะได้ช่องขวาที่ว่างเปล่าเป็นส่วนใหญ่
> เหตุผลอยู่ในตารางข้างล่าง มีข้อเสนอแทนอยู่ท้ายเอกสาร

---

## 1. ของจริงเป็นอย่างไร

`HOME_SECTION_KEYS` มี 9 คีย์ที่ลากจัดลำดับและซ่อนได้ ส่วน hero / gallery / cta
เป็นอีกเรื่องหนึ่ง — hero เป็นแบนเนอร์หมุน ไม่ใช่บล็อกเนื้อหา และ cta เป็นโครง
ของหน้า ทั้งคู่จึงไม่มีแถวใน `HomeSection` เลย (ดู comment บน `HOME_SECTION_KEYS`)

| # | section (เรียงได้/ซ่อนได้) | ฟอร์มที่แก้เนื้อหาอยู่ที่ไหน |
|---|---|---|
| 1 | `COMPANY_INTRO` | ข้อความ: **เกี่ยวกับเรา → เรื่องราวบริษัท** · รูป: **หน้าแรก → แกลเลอรี** |
| 2 | `VISION_MISSION` | **เกี่ยวกับเรา → หลักการทำงาน** |
| 3 | `FEATURED_PROJECTS` | *อัตโนมัติ* — โครงการที่เผยแพร่ เรียงตาม `sortOrder` |
| 4 | `CORPORATE` | **เกี่ยวกับเรา → บริการของบริษัท** |
| 5 | `AWARDS` | **เกี่ยวกับเรา → รางวัล** |
| 6 | `WHY_US` | **เกี่ยวกับเรา → ทำไมต้องเรา** |
| 7 | `UPCOMING_EVENT` | *อัตโนมัติ* — กิจกรรมถัดไปที่เผยแพร่ |
| 8 | `LATEST_NEWS` | *อัตโนมัติ* — บทความล่าสุดที่เผยแพร่ |
| 9 | `FAQ` | **หน้าเว็บไซต์ → คำถามที่พบบ่อย** |
| — | hero (ไม่อยู่ในลำดับ) | **หน้าแรก → แบนเนอร์** |
| — | cta (ไม่อยู่ในลำดับ) | **หน้าแรก → CTA ปิดท้าย** |

**นับดู: ไม่มี section ใดใน 9 คีย์ที่ฟอร์มอยู่ใต้ `/admin/pages/home` เลย**
3 คีย์ดึงข้อมูลอัตโนมัติ · 6 คีย์แก้ที่แท็บ "เกี่ยวกับเรา" หรือ "คำถามที่พบบ่อย"
ส่วนสามหน้าที่อยู่ใต้ `/pages/home` จริง ๆ (แบนเนอร์ แกลเลอรี CTA) กลับ
**ไม่ได้อยู่ในลำดับ** ที่หน้า sections จัดการ

แปลว่าถ้าทำตาม mockup ตรง ๆ ช่องขวาจะเป็น "ลิงก์ไปที่อื่น" 9 จาก 11 แถว —
ซึ่งไม่ได้ลดการสลับหน้า แค่ย้ายที่กดปุ่มสลับ

## 2. เหตุผลที่ mockup วาดแบบนั้นได้ และทำไมถึงไม่ตรง

mockup สมมติว่า "section ของหน้าแรก" เป็นเนื้อหาที่เป็นของหน้าแรก จริง ๆ แล้ว
หน้าแรกของเว็บนี้เป็น **หน้ารวม**: มันหยิบเนื้อหาของหน้า "เกี่ยวกับเรา" กับ
"คำถามที่พบบ่อย" มาแสดงซ้ำ แล้วเพิ่มรายการที่ดึงอัตโนมัติอีกสามชุด
สิ่งที่หน้าแรก "เป็นเจ้าของ" จริง ๆ มีแค่สามอย่าง: แบนเนอร์ แกลเลอรี และ CTA

เอาเนื้อหาเหล่านั้นมาแก้ในหน้าแรกด้วยจะเกิดปัญหาที่หนักกว่าเดิม: แก้ "รางวัล"
จากหน้าแรกก็คือแก้หน้า "เกี่ยวกับเรา" ไปด้วย โดยที่หน้าจอไม่ได้บอก
(ซึ่งเป็นปัญหาเดียวกับที่เฟส 4 เพิ่งแก้ไป — `settings/company` แก้หน้า About
อยู่โดยไม่บอกใคร)

## 3. ข้อเสนอแทน — "แผงควบคุมหน้าแรก" หน้าเดียว ไม่ใช่ page builder

รวมสี่แท็บ (`sections` / `hero` / `gallery` / `cta`) เป็นหน้าเดียวที่
**เรียงตามลำดับที่ปรากฏจริงบนหน้าเว็บ** แต่ละแถวบอกสามอย่าง: ลำดับ, สวิตช์
ซ่อน/แสดง, และ *ใครเป็นเจ้าของเนื้อหานั้น*

```
หน้าแรก
┌──────────────────────────────────────────────────────────┐
│ [แบนเนอร์]              3 สไลด์            [แก้ที่นี่ ▾] │  ← ขยายในหน้า
│ ─────────────────────────────────────────────────────── │
│ ⠿ 1  แนะนำบริษัท        ซ่อน/แสดง ●        [ข้อความ →]  │  ← ลิงก์ออก 2 ที่
│                                              [รูป ▾]     │  ← ขยายในหน้า
│ ⠿ 2  วิสัยทัศน์          ซ่อน/แสดง ●        [แก้ →]      │
│ ⠿ 3  โครงการเด่น        ซ่อน/แสดง ●        อัตโนมัติ ⓘ  │
│ ⠿ 4  บริการของบริษัท     ซ่อน/แสดง ○        [แก้ →]      │
│ …                                                        │
│ ─────────────────────────────────────────────────────── │
│ [CTA ปิดท้าย]           ปิดท้ายเสมอ        [แก้ที่นี่ ▾] │  ← ขยายในหน้า
└──────────────────────────────────────────────────────────┘
```

- **สามแถวที่หน้าแรกเป็นเจ้าของจริง** (แบนเนอร์ · แกลเลอรี · CTA) กางฟอร์มในหน้า
  — นี่คือส่วนที่ลดการสลับหน้าได้จริง และเป็นสามแท็บที่หายไป
- **หกแถวที่เป็นของหน้าอื่น** เป็นลิงก์ พร้อมบอกว่าจะไปไหน
  ("แก้ที่ เกี่ยวกับเรา → รางวัล") ไม่ใช่ปุ่มลอย ๆ
- **สามแถวอัตโนมัติ** ไม่มีฟอร์ม มีแต่ ⓘ อธิบายว่าดึงจากอะไรและลิงก์ไปแหล่งนั้น
  (โครงการ / กิจกรรม / ข่าวสาร) — ทุกวันนี้ไม่มีอะไรบอกเลยว่าทำไมแก้ไม่ได้
- **ลากจัดลำดับ** เปลี่ยนจากปุ่มขึ้น/ลงเป็นลากได้ แต่ *ไม่บังคับ* — ปุ่มขึ้น/ลง
  ทำงานได้อยู่แล้วและใช้ได้ด้วยคีย์บอร์ด ถ้าจะทำต้องเก็บปุ่มไว้เป็น fallback

### state เก็บที่ไหน

`?section=hero` ใน URL แถวที่กางอยู่จึงรอด refresh และส่งลิงก์ให้คนอื่นได้
(หลักเดียวกับ `?lang=` และ `?item=` ที่ใช้อยู่ทั้งหลังบ้าน) ไม่มีค่า = ไม่กางแถวไหน

### route เดิม

`/pages/home/{hero,gallery,cta}` **คงไว้เป็น route จริง ไม่ redirect**
สองเหตุผล: สามหน้านั้นเป็นฟอร์มขนาดจริง (แกลเลอรีเป็นรายการรูปทั้งชุด)
การยัดลงแผงเดียวจะทำให้หน้ายาวมากเมื่อกางพร้อมกัน และเทสกับลิงก์ภายใน
(`lib/media-usage.ts` ชี้ `/admin/pages/home/hero`) ยังใช้ path เดิมอยู่
แถว "แก้ที่นี่" จึงกางแบบ progressive: กางในหน้าได้ และมีลิงก์ "เปิดเป็นหน้าเต็ม"
ไปที่ route เดิมเสมอ

ถ้ายืนยันว่าจะ redirect จริง ๆ ต้องเพิ่มใน `next.config.js` และใส่ alias ตามกติกา
ของทุกเฟส

## 4. ขอบเขตงานโดยประมาณ

| งาน | ประเมิน |
|---|---|
| รวมสี่แท็บเป็นแผงเดียว + `?section=` + แถวอัตโนมัติมี ⓘ | 1.5–2 วัน |
| ลากจัดลำดับ (เก็บปุ่มขึ้น/ลงไว้เป็น fallback) | +1 วัน |
| เทส: ลำดับ/การซ่อนยังบันทึกถูก, ทุกแถวมีปลายทางจริง | +0.5 วัน |

ไม่แตะ schema · ไม่แตะ `HOME_SECTION_KEYS` · ไม่แตะ `SECTION_RENDERERS`

---

## 5. ต้องตัดสินใจก่อนเริ่ม

1. **เอาข้อเสนอนี้ หรือยืนยันตาม mockup เดิม** (ซ้ายรายการ ขวาฟอร์ม)
   ถ้าเอาตาม mockup เดิม ต้องรับว่าช่องขวาส่วนใหญ่จะเป็นลิงก์ ไม่ใช่ฟอร์ม
2. **ลากจัดลำดับ จำเป็นไหม** — ปุ่มขึ้น/ลงทำงานได้อยู่แล้ว และเข้าถึงง่ายกว่า
3. **route เดิมสามอัน คงไว้ (แนะนำ) หรือ redirect เข้าแผง**
