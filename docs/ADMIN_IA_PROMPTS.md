# แผนการทำงาน 6 เฟส + คำสั่งสำหรับ Claude Code

คู่กับ `docs/ADMIN_IA_BLUEPRINT.md` (เอกสารออกแบบ) — ไฟล์นี้คือ **ลำดับการลงมือ**
แทนที่หัวข้อ 7 ของ blueprint ซึ่งเดิมแบ่งไว้ 5 เฟส

## วิธีใช้

คำสั่งอยู่ใน `.claude/commands/` เปิด Claude Code ใน VS Code แล้วพิมพ์:

```
/ia-phase-1
```

ต่อท้ายด้วยข้อความอะไรก็ได้เพื่อเพิ่มข้อจำกัดเฉพาะครั้ง เช่น

```
/ia-phase-3 ทำเฉพาะกลุ่ม Home ก่อน About ไว้ทีหลัง
/ia-phase-5 translations
/ia-phase-6 2
```

แต่ละคำสั่งจะเช็คเองว่าเฟสก่อนหน้าเสร็จหรือยัง และหยุดถ้ายัง

---

## ทำไมแบ่งแบบนี้

หลักเดียว: **แต่ละเฟส deploy ได้เอง และตอบคำถามได้ว่า "ถ้าพังจะพังเพราะอะไร"**

| | ถ้าเฟสนี้พัง | จะรู้ได้เพราะ |
|---|---|---|
| 1 | สิทธิ์ผิด | เทสสิทธิ์ที่เพิ่มในเฟสเดียวกัน |
| 2 | เมนูเพี้ยน | UI ต้องเหมือนเดิมทุกพิกเซล — ต่างแม้นิดเดียวคือบั๊ก |
| 3 | หน้าหาย / URL พัง | e2e + ตาราง redirect |
| 4 | คนเข้าผิดหน้า | เทส role ต่อโซน |
| 5 | หน้าใหม่ผิด | ไม่กระทบของเดิมเลย |
| 6 | build พัง | `npm run verify` |

ที่แยกเฟส 2 ออกจากเฟส 3 เพราะเฟส 2 คือ refactor ล้วน ๆ ที่ผลลัพธ์ต้อง **ไม่เปลี่ยนอะไรบนจอ**
พอเฟส 3 มีอะไรเพี้ยน จะรู้ทันทีว่าเป็นเรื่อง IA ไม่ใช่เรื่อง refactor — ถ้ารวบสองเฟสนี้เข้าด้วยกัน จะแยกไม่ออก

## ทั้ง 6 เฟส

| # | คำสั่ง | ทำอะไร | ประเมิน | ขึ้นกับ |
|---|---|---|---|---|
| 1 | `/ia-phase-1` | แก้บั๊กสิทธิ์ 4 จุดที่ audit เจอ + เทสคุม | 0.5 วัน | — |
| 2 | `/ia-phase-2` | ย้าย nav config → `lib/admin/nav.ts` (จอเหมือนเดิม) | 1 วัน | 1 |
| 3 | `/ia-phase-3` | **ยุบ 10 เมนู section เข้าเป็น Tab ใต้ `/admin/pages`** | 2–3 วัน | 2 |
| 4 | `/ia-phase-4` | Route group + guard ต่อโซน + เปิด VIEWER อ่านอย่างเดียว | 1–2 วัน | 3 |
| 5 | `/ia-phase-5` | หน้าที่ขาด: คำแปล, 404, สถิติ, สุขภาพคลังไฟล์, OG image | 3–5 วัน | 4 |
| 6 | `/ia-phase-6` | อัป dependency 7 ขั้น เรียงตามความเสี่ยง | 2–3 วัน | — |

**เฟส 6 แทรกเมื่อไหร่ก็ได้** ไม่ขึ้นกับเฟสอื่น แต่ถ้าจะทำขั้นที่ 5 (Next 16) ควรทำหลังเฟส 3 จบ
เพราะการย้าย `middleware.ts` → `proxy.ts` พร้อมกับย้ายโฟลเดอร์ทีเดียว จะทำให้ debug ยากขึ้นโดยไม่จำเป็น

### ถ้าเวลาจำกัด

เอาแค่ **เฟส 1 + เฟส 3** ก็แก้ปัญหาที่ถามมาได้แล้ว (Sidebar รก + สับสน + สิทธิ์ผิด) — ประมาณ 3–4 วัน
เฟส 2 จะกลายเป็นหนี้ที่ต้องใช้คืนตอนแก้เมนูครั้งถัดไป แต่รับได้ถ้าเร่ง

## กติกาที่ใช้กับทุกเฟส

- **หนึ่งเฟส หนึ่ง branch หนึ่ง PR** — อย่าให้เฟสเหลื่อมกัน
- `npm run verify` คือประตู อย่ารายงานว่าเสร็จถ้ายังไม่ผ่าน (ตาม `AGENTS.md`)
- เฟส 3 และ 4 ต้องผ่าน `npm run test:e2e` ด้วย — **หยุด `npm run dev` ก่อนรัน** (เหตุผลอยู่ใน `AGENTS.md`)
- ถ้า Claude เจอปัญหานอกขอบเขตของเฟสนั้น ให้ **รายงานอย่างเดียว ห้ามแก้** — คำสั่งทุกอันเขียนกำกับไว้แล้ว
- ก่อนเริ่มเฟส 3 ให้ tag ไว้สักจุด: `git tag pre-ia-phase-3` — เป็นเฟสเดียวที่ย้ายไฟล์เยอะ

## สิ่งที่ต้องตัดสินใจก่อนเริ่ม

สองข้อนี้คำสั่งไม่ตัดสินให้ เพราะเป็นเรื่องนโยบายไม่ใช่เรื่องเทคนิค

1. **VIEWER ควรเห็นอะไรบ้าง** — เฟส 4 ตั้งไว้ว่า "อ่านได้ทั้ง Properties และ Website Content"
   ถ้าอยากให้แคบกว่านั้น (เช่น เห็นแค่ Dashboard + รายงาน) บอกก่อนเริ่มเฟส 4
2. **ทีมขายควรแก้ roster ทีมขายเองได้ไหม** — เฟส 1 ตั้งไว้ว่า SALES **ดูได้ แก้ไม่ได้**
   ถ้าอยากให้หัวหน้าทีมขายแก้ได้ ต้องเพิ่ม capability ใหม่ ไม่ใช่ลด minRole ของทั้งหน้า

## หลังจบทั้ง 6 เฟส

สิ่งที่ยังเหลือใน backlog (จาก `docs/ADMIN_IA_BLUEPRINT.md` §5) เรียงตามความคุ้ม:

- **P2** — Core Web Vitals · IndexNow · Search Console API · Backup/Export · หน้าค้นหาสำหรับมือถือ
